# ADR 0003 — One check script, three CI jobs

## Status
Accepted, 29 August 2026.

## Context
The project had 236 tests and nothing that ran them. Green was whatever the last
person remembered to type, which across three toolchains — Python, Node and
Gradle — is not a state anyone can hold in their head.

## Decision
`scripts/check.sh` is the single entry point, run identically by a person and by
CI. A pipeline that runs different commands from the ones developers use is a
pipeline that fails for reasons nobody can reproduce locally.

CI splits it into three jobs rather than one, so a Kotlin failure does not hide
a Python one, and the slowest surface (mobile, which assembles two APKs) never
gates feedback on the fastest.

The backend job runs against a real PostgreSQL 16 service, not SQLite. Seat
booking rests on `SELECT … FOR UPDATE SKIP LOCKED`, which SQLite does not have;
testing it on a substitute would prove nothing about the mechanic the product
depends on.

## Consequences
`npm ci` needs `admin/package-lock.json` committed, and the mobile job needs the
Gradle cache to stay warm or it will be slow. Neither is a real cost.

The script exits non-zero on the first failing surface but still reports every
step it ran, so one push shows every broken thing rather than one at a time.

Verified by breaking a rule the tests guard — removing the payout direction
check — and confirming the script reports `✗ backend e2e` and exits non-zero.
